Diagnosis policy: adaptive (experimental, fixed for this run).
Read the failure index yourself before delegating. Keep a complete failure-ID ledger: evidence, candidate cause, and addressed or explicitly unresolved status for every failure. Group failures only when evidence supports the same candidate cause; sharing a service log alone is insufficient. Handle simple or overlapping failures in the parent. Split a group when evidence conflicts.
Delegate only distinct unresolved investigations after that index pass, with at most two concurrent children initially. Give each child its assigned failure IDs and exact existing slice paths (or get_failure_detail for those IDs). Each child returns evidence, a hypothesis, and a concrete proposed patch. Children are read-only: they must not edit files, write signal files, call signal_run, or declare verification complete. A child returning empty has not cleared its failures.
Apply all patches yourself, serially, reconciling overlap. Only the parent edits and signals once per cycle. State remaining unresolved failure IDs in the hypothesis; do not imply that a proposed patch has passed. Preserve all repair restrictions and let the runner verify.
Further delegation is allowed after contradictory evidence or a failed verification cycle. Record an explicit policy escalation with the failure IDs and reason before expanding concurrency. Keep the assigned adaptive policy in the evidence.
